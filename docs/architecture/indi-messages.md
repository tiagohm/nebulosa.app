# INDI Messages Contract

Part of the [architecture](../ARCHITECTURE.md) of Nebulosa.

- `IndiMessageService` (`api/src/indimessages.ts`) is the one collector of the INDI protocol `<message>` elements: one `message` handler in `DeviceRegistry.handler`, for the open client of each INDI connection (the simulator and the Alpaca client send none, and their messages would be ignored). Only the `device` attribute routes a message, never its text, and nothing is inferred from it (no severity). The `message` attribute of `def*Vector`, `set*Vector`, and `delProperty` is never collected: it stays with the vector in INDI Properties.
- Text is driver input: control characters (but tab and line feed) and bidirectional marks and overrides are removed, line breaks normalized, and the ends trimmed (`messageText`); a message left blank is ignored. A repeated text is a new occurrence, with its own id. The driver's `timestamp` is kept as sent, never parsed; `receivedAt` (Unix ms) is the instant of receipt.
- A message without a device, or with an empty one, is the INDI server's own: published through the `ServerEventDispatcher` as `indi:globalMessage` (its text on one line), which the classifier records as an `info` notification `indi.globalMessage` (see [Notifications Contract](notifications.md)). At most `GLOBAL_MESSAGE_LIMIT` (8) per connection pass in each `GLOBAL_MESSAGE_WINDOW` (60 s), a fixed window that starts with the first message it admits; the first one over the limit publishes one `indi:globalMessagesSuppressed` instead, and the rest of the window is dropped, so a noisy server never crowds the 500 records of the shared history. The window starts over with the connection.
- A message for a device is kept in memory under the hardware id `makeHardwareId` gives the exact driver-reported name (case and spaces included), so a device not defined yet is kept under the id it gets once defined: the latest `MAX_DEVICE_MESSAGES` (100) per device, each cut to `MAX_MESSAGE_TEXT` (2048) characters and marked `truncated`, for at most `MAX_MESSAGE_DEVICES` (128) devices per connection, the least recently active dropped first. Each message has a `sequence` increasing per device, so a first kept message above 1 says older ones were dropped. They are collected whether or not a tab looks; nothing is stored on disk, no operation runs, and no device is held. The history belongs to the open client: a new client starts a new epoch with nothing kept, and the close of the connection (`connection:close`) drops it; the removal of a device ends its subscriptions and keeps its history for the session.
- The message stream of one physical device (`connectionId`, `hardwareId`) reaches only the sockets that sent `indi:messagesSubscribe` for it: an `indi:messagesSnapshot` (the kept messages, oldest first), sent on that socket in the same tick, then one `indi:messageReceived` per new message. A refused subscription gets `indi:messagesSubscriptionError`: `notFound` when the connection is not open or has no device with exactly that hardware id in its directory, `unsupported` when the connection is not an INDI server. Subscribing again resends the snapshot; `indi:messagesUnsubscribe`, the close of the socket, the removal of the device, or the close of the connection end it. Each event carries the client's `epoch` and a `revision` increasing across the service. A socket with more than `MAX_BUFFERED_AMOUNT` (1 MiB) queued, or that queued or dropped a send, skips the new messages until it drains, then receives a fresh snapshot.
- The web view (`IndiMessagesPanel`, `messages.ts`, `useIndiMessages.ts` of `web/src/equipment-control/indi/`) is the Messages view of a device of an INDI connection in Equipment Control, `/equipment/<device id>/messages`, managed or not; a connection of another type has no such view, and a message never opens it. `indiMessagesView` is not a server store but the stream of the one device shown: the view subscribes while mounted, its device is in the directory, and the page is visible (a hidden page pauses it and keeps what is shown), subscribes again on every socket open, keeps what it shows marked disconnected while the socket is closed, drops events of another epoch or older than what it applied, and unsubscribes when it unmounts or changes device. Messages are listed oldest first with the instant of receipt in the display zone (the driver timestamp in the tooltip), as text only; a search filters them by text, ignoring case; Follow latest keeps the end in view until the list is scrolled away from it; Copy puts the listed messages on the clipboard, one tab-separated line each (instant, device, text).
- Limitations: the history lives only while the connection is open and in the server's memory; a restart or a reconnection forgets it. A global message is the INDI server's own text, recorded as sent (cleaned of control characters, cut to 240 characters): a driver can put a path or an address there, and nothing redacts it.
