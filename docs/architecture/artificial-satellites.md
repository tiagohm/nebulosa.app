# Artificial Satellites Contract

Part of the [architecture](../ARCHITECTURE.md) of Nebulosa.

- Catalog (`api/src/satellites.store.ts`, see [Persistence and State](persistence-and-state.md)): objects by NORAD catalog number, always a canonical decimal string of any length (six- and nine-digit ids included, never a number or a five-digit pattern), with their SATCAT metadata when read, one GP and one imported element set each, and group memberships. A group is a membership of the source that listed the object, never a category, and an object is kept with its other groups, metadata, and elements when a group stops listing it. An object without elements is metadata only: searchable, never predicted. The element set the predictions use is the one an operator chose (`PUT /api/satellites/:noradId/element-source`), else GP, else imported, never the most recently downloaded. Search (`GET /api/satellites`) is local, never the network: an exact NORAD id (leading zeros ignored) or international designator first, then names starting with the text, then names containing it, case and diacritics ignored, filtered by group, SATCAT type, status, and a list of ids, paged by offset (at most `SATELLITE_SEARCH_LIMIT`, 100, per page; 50 by default) with its total. `GET /api/satellites/:noradId` answers the details of one object and `GET /api/satellites/sources` the state of every source.
- Element sets (`api/src/satellites.elements.ts`): every set, downloaded or imported, is validated once by the toolkit (`validateOMM`, `validateTLE`: frame, center, time system, theory, numbers, epoch, eccentricity, mean motion, SGP4 initialization) and stored as a canonical OMM (CCSDS keywords in a fixed order, numbers as numbers) whose SHA-256 is its identity; a set that fails is never stored and is counted with its reason. Imports (`POST /api/satellites/import`) take OMM JSON or TLE text (two lines, optionally after a name line, Alpha-5 numbers converted) and make the imported set the one the object uses; a text that is neither is `422 invalidImport`. Every prediction names its set (`elements`: digest, epoch, kind, source key), so two results from different sets are never confused.
- Downloads (`api/src/satellites.sync.ts`, `satellites.celestrak.ts`) follow the CelesTrak usage policy (https://celestrak.org/usage-policy.php): only when an operator asks (`POST /api/satellites/sources/:sourceKey/refresh`) or for the groups an operator turned on for automatic downloads, never when the Sky or the tool opens, a selection changes, or time is animated; only allowlisted queries (`gp` or `satcat`, `GROUP` of a fixed list of current-data groups or `CATNR`), always `FORMAT=JSON` from `https://celestrak.org`, with the Nebulosa `User-Agent` (`identifyCelestrakClient`) and redirects not followed; one request at a time for the process and one shared download per source. A source is downloaded at most once per GP update (2 hours) or SATCAT interval (24 hours); the attempt is recorded before the request, so a failure or a crash never leads to a repeat, and a refresh inside the interval is `409 sourceCooldown` with the cached data untouched. Any answer other than 200 or no answer blocks the source for its interval, doubled by each failure since the last success up to a day and at least the `Retry-After` asked for (`409 sourceBlocked` meanwhile); a 301, 403, 429, or 5xx blocks every source, since CelesTrak firewalls clients that keep sending errors. The interval and blocks are kept in `satellite_sources` across restarts. An answer that is not a JSON list, or a group that answers nothing while it listed objects, is `502 invalidResponse` and replaces nothing; a single object without GP data is an empty answer. A GP download of a group that is not large (not ACTIVE, STARLINK, or ONEWEB) also downloads the SATCAT of the group when its own interval allows, whose failure never fails the first. Each successful download is published in one transaction and then `satellites:changed` carries a new revision.
- Automatic downloads (`api/src/satellites.auto.ts`, `SatelliteAutoDownload`): the allowlisted groups turned on (`PUT /api/satellites/sources/:sourceKey/auto-download` with `{ enabled }`, the GP source key of a group only, else `404 notFound`; kept in `satellite_auto_downloads`, large groups included) are downloaded once when the server starts (`startSatelliteDownloads`, after the database) and then by an in-process `Bun.cron` job every 6 hours (`0 */6 * * *`, the server's time zone), one after the other through the same downloads as an operator's, so the 2-hour GP interval, the SATCAT interval, and the blocks hold: a group not allowed yet waits for a later run, and a failure is recorded in its source and never stops the other groups or the schedule. A run joins the one in progress; a hot reload of the server stops the job before the next run starts again. A large group downloads its elements only, as when asked. Turning a group on downloads nothing by itself and publishes `satellites:changed`.
- Predictions (`api/src/satellites.ephemeris.ts`) use only the toolkit's SGP4 and frames, from a prepared record per element digest, copied for every computation since SGP4 writes into a record as it propagates. Positions (`/position`, `/ephemeris`, `/tracks`) are geometric: no light time (a few milliseconds) and no annual aberration, which a satellite moving with the Earth does not show; topocentric for an observer and geocentric without one, labeled by `center`. RA/Dec are given of date (true equator and equinox, the frame of the Sky map) and in ICRS (J2000); altitude is geometric, with `apparentAltitude` refracted by the model of the Sky; distances are km, rates km/s and radians per second. Illumination is the toolkit's conical umbra and penumbra, with the Sun interpolated between hourly VSOP87E positions (0.01″). `/ephemeris` samples at most 5000 rows (`truncated` beyond them), letting the event loop run every 250 rows. Satellites have no rise, transit, and set events.
- Passes (`/passes`, the tool keeps the window within 7 days): the intervals above a minimum geometric altitude (`satelliteWindowPasses`), searched a day at a time with the event loop running between days and a pass cut by a day boundary joined again, at most 200. A pass in progress at an edge of the window is kept with its bound at the edge (`startsBeforeWindow`, `endsAfterWindow`), never shown as a rise or set, and a geostationary satellite above the mask is one pass over the whole window. The culmination is the highest point within the window, not a meridian transit or the closest approach. Each pass lists its visible parts: sunlit (outside the umbra) while the observer's Sun is below the twilight limit given; no brightness is estimated, since no source gives the standard magnitude of most objects, so brightness is unknown and never filters. A cancelled request stops computing.
- Quality of every prediction (`quality`): the age of the elements (instant minus epoch, in days, the worst over a window) against policy limits by orbit (below 225 minutes: caution after 3 days, unavailable after 14; higher: 14 and 60), the decay date of the catalog, an SGP4 failure, and whether the Earth orientation tables hold the instant; `usable`, `caution`, or `unavailable` with its reasons. These are conservative limits, not error bars. Passes are refused when unavailable (`422 predictionUnreliable` with `quality`); positions and ephemerides answer with their quality; an SGP4 failure is `422 predictionUnreliable`. A metadata-only object is `404 noElements`, an unknown one `404 notFound`.
- Ground tracks (`POST /api/satellites/:noradId/ground-track` with `{ time, orbits }`, `SatelliteGroundTrackResponse`): samples from one orbit before the instant to 1 to 5 orbits after it (`GROUND_TRACK_MAX_ORBITS`), at most 3 days in all (`GROUND_TRACK_MAX_MS`), every period/180 between 10 s and 5 minutes in whole seconds, at most 5000, in parallel arrays: the geodetic subpoint (`satelliteSubpoint`, IERS2010, longitude in (−π, π]) and height, the footprint as the geocentric half-angle of the region that sees the satellite above the horizon (`satelliteGroundFootprint`: a spherical Earth with an ideal horizon, without terrain, refraction, or a minimum altitude), the shadow state, and the subsolar point (the toolkit's `subpoint` of the interpolated VSOP87E Sun). It needs no observer, lets the event loop run every 250 samples, carries the elements and the quality of its window, and is never refused for the age of the elements; an SGP4 failure is `422 predictionUnreliable`.
- Tracks for the Sky (`POST /api/satellites/tracks`): samples of RA/Dec of date, geometric altitude, and sunlit state of the ids asked for and of the members of a group above the observer's horizon at the start (by the look angles alone, highest first; the first by id without an observer), at most 50 objects and 20 000 samples, each with its elements and quality or the code of its failure.
- Sky identity (`api/src/sky/`): a satellite is the `SkyObjectRef` `{ kind: 'satellite', noradId }` (key `satellite:<id>` in the web) of category `satellite`. `GET /api/sky/search` lists at most 5 satellites of the local catalog after the bodies and constellations, never asking the network; `POST /api/sky/position` locates a satellite through the satellite service (`SkySatellites`, `satelliteSkyAdapter`) as a `SkyPosition` of source `local` with the refracted altitude, the distance in AU, and no magnitude or events, `404 noElements` for a metadata-only one and `422 predictionUnreliable` when SGP4 fails. The Sky locator of the mounts has no satellite target, so no mount is ever sent to one.
- Sky map (`web/src/sky/satellites.sky.ts`, `satellites.track.ts`): the selected satellite and the profile's favorites, at most `SATELLITE_TRACKS_LIMIT` (50), are moving bodies of type `satellite` drawn at every zoom by the map layer of their own, `satellites` (`MovingBodyLayer` and `movingBodyLayerId` of `web/src/sky/celestial/`), which the display layer Artificial satellites shows or hides (`satellites` of `SKY_LAYERS`, shown by default) apart from the Solar system layer. Hidden, no satellite is drawn or sampled, the selected one and its track included. Their positions come from one `/tracks` request per window of 60 samples around the Sky clock's instant (about ten real minutes at the clock's rate, from 10 minutes to 6 hours, starting a tenth before the instant, aligned to its step), asked again only when the instant leaves the window or the ids, the observer, or the catalog revision change, and placed between samples by spherical linear interpolation, never a new prediction. The markers move every 250 ms (1 s with reduced motion) while the page is shown, apart from the 15 s tick of the map, since each move rebuilds the pick index.
- Satellite Inspector (`web/src/sky/satellite/`, `skySatelliteState`, tab memory): the Object Inspector of a satellite, with its identity, the Brightness Unknown, the position of the selection (geometric, of date and J2000, distance in km, geocentric without an observer), the altitude and azimuth, the next pass above the horizon within two days of the Sky's instant on request (Show Next Pass, visible parts with the Sun below civil twilight), and the orbital data. Track on Sky pans the view to the satellite at every marker update until the map is panned (the projection never moves, so a satellite outside the equatorial chart's hemisphere cannot be centred); Show Track draws the samples of its window as a dashed line, broken below the horizon; Open in Artificial Satellites opens the tool on it. No Slew, Framing, rise, transit, or set is offered.
- Favorites are a profile preference the server keeps (`ProfileSettings.satelliteFavorites`, see [Persistence and State](persistence-and-state.md)); a refresh never removes an id it stops listing. The web mirrors the sources (`satelliteCatalogState` of `web/src/satellites/satellites.ts`, in `SERVER_STORES`), whose revision the views watch to read their own data again after a change.
- Not provided: SupGP, the Sky display of a whole group (the API samples one), satellite brightness and flares, conjunction or collision screening, trails over images, transits of the Sun or the Moon, and tracking with a mount.
